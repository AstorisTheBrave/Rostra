## Develop and run

Install Node.js `22.22.2+` or `24.15.0+` (or a supported later major) and Corepack 0.35.0. Use the root frozen pnpm lockfile. The canonical contributor setup is in [CONTRIBUTING.md](../../CONTRIBUTING.md); production Compose procedures are in the [deployment runbook](../runbooks/deployment.mdx).

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm prisma:generate
```

The root scripts start the gateway by default and expose separate apps for development:

- `pnpm dev` - gateway with tsx watch
- `pnpm start` - Discord gateway
- `pnpm start:api` - API
- `pnpm start:workers` - durable workers
- `pnpm start:web` - web app
- `pnpm start:realtime` and `pnpm start:activity` - optional apps
- `pnpm deploy:commands` - publish slash-command definitions to Discord

The last command has a live external effect. It is not part of migration verification, tests or service smoke.

## Quality checks

- `pnpm check:boundaries` - repository, workspace and package boundaries
- `pnpm typecheck` - generate the database client, then strict TypeScript
- `pnpm lint` - package lint plus root Biome check
- `pnpm test` - unit tests with placeholders supplied by the caller or CI
- `pnpm test:env` - direct Node test run loading local `.env`
- `pnpm test:integration` - worker restart/delivery proof; needs disposable PostgreSQL and Redis
- `pnpm build` - all workspace build tasks
- `pnpm test:browser --project=chromium` - browser smoke; needs generated client and disposable database/cache services

## Data and service boundaries

PostgreSQL is required and owns durable application state and operation intent. Redis backs shared cache and at-least-once queue delivery. Some local paths have an in-memory fallback, which is not a substitute for shared Redis in a multi-process deployment. Migration commands use a direct PostgreSQL URL.

Gateway configuration lives behind `@rostra/config`. API, web and workers can run independently. Web does not query the database directly. Realtime and Activity remain disabled in the default Compose profile. Web sessions are process-local, so multiple web instances are not supported.
