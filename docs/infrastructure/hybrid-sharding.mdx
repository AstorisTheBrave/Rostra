# Hybrid sharding

The gateway has an opt-in hybrid mode implemented with `discord-hybrid-sharding`. It starts a local
process-mode `ClusterManager`; `TOTAL_SHARDS` sets the fleet count and `SHARDS_PER_CLUSTER` controls the
local cluster size. `SHARDING_MODE` defaults to `native`. The implementation also has a Redis-backed
identify lock and leader lease for coordinating cluster startup and manager jobs.

This mode has not been verified against Discord credentials or at production scale in the Phase 00 gate.
The local migration and service tests use fake credentials and do not connect a gateway. Do not infer
multi-host support or capacity from the implementation or configuration alone. Measure and validate the
intended topology in a controlled environment before production. See the [environment reference](env.mdx),
[deployment runbook](deployment.mdx), and [capability status](../product/capability-status.mdx).
