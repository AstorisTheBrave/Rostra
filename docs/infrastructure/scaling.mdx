# Scaling and deployment

The current supported deployment path and configured resource limits are documented in the
[deployment runbook](deployment.mdx). Use the [recovery runbook](../runbooks/recovery.mdx) for rollback and
data recovery. The [capability status](../product/capability-status.mdx) distinguishes implementation
from locally tested and externally verified behavior.

Older versions of this page described hybrid multi-host clustering, Redis-driven live updates, zero-downtime
deploys and production-scale capacity. Those claims are not established by the current implementation and
have been removed. Do not infer shard capacity from repository configuration or local smoke tests. Measure a
representative workload before planning production resources.

The current Compose configuration has bounded per-service CPU and memory limits. It supports a passive
reverse proxy or tunnel at the documented app endpoints. Multi-instance web sessions require shared durable
storage and are not supported by the current process-local session store. Rostra does not provision DNS,
TLS, cloud services or ingress-provider resources.
