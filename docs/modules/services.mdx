## what this is

The three shared "always-on" helpers every part of Rostra uses: a logger (records what's happening), a
database connection (saves and reads data), and a cache (remembers hot data quickly). Each is a single
shared instance so the whole bot reuses one connection instead of making new ones everywhere.

## technical map

**file paths**
- `packages/logger/src/index.ts` - Pino logging
- `packages/database/src/index.ts` - Prisma/Postgres access
- `packages/cache/src/index.ts` - Redis/Keyv cache
- tests live beside each package owner

**exports**
- `getLogger(scope): Logger` - cached child logger tagged with `scope`; `logger` is the root.
- `getPrisma(): PrismaClient` - cached singleton DB client; `disconnectPrisma()` for shutdown.
- `getCache(): Keyv` - cache (Redis-backed if `REDIS_URL`, else in-memory).
- `getRedis(): Redis | undefined` - raw ioredis client for sorted-set ops (leaderboards); undefined w/o Redis.
- `cacheGet/cacheSet/cacheDel/withCache` - typed convenience helpers; `disconnectCache()` for shutdown.
- `createCoherentCache(owner, scope)` + `commitCoherentWrite(identity, writer, onCommit)` -
  bounded local caches for persisted configuration and preferences. Misses read PostgreSQL
  directly. A write advances its revision with the data in one transaction and publishes
  the exact identity after commit. `CONFIG_TTL_MS` is 300,000 (five minutes).

**`apps/gateway/src/services/tenant.ts`** - the centralized per-guild config ("tenant", model `GuildTenant`).
- `getTenant(guildId)` - bounded local cache of hot guilds, then PostgreSQL (lazily upserts
  the row). Versioned invalidations evict other processes after a committed write.
- `updateTenant(guildId, patch)` - writes the row and publishes a versioned invalidation.
  The setup wizard writes channel/role ids and feature flags here.
- `isFeatureEnabled(tenant, name)`, `getSetting(tenant, key)`, `setFeatures(guildId, flags)`,
  `evictTenantL1(guildId)`.

**Scheduled work** - `packages/operations/src/scheduler.ts` owns durable `ScheduledTask` claims,
retry and settlement. The tracked worker poller publishes only task ID and claim version through
`@rostra/cache/bus`. The gateway adapter accepts an exact claim on the guild-owning process, or on
shard 0 for global work, then invokes the registered Discord handler. The gateway `schedule` facade
creates a row without a timer or Client argument. `cancelTask(id)` returns `cancelled`, `processing`,
`terminal` or `missing`; cancellation cannot reverse an effect already processing. Failed and cancelled
rows remain for inspection. `runAt` remains the original due time while `nextAttemptAt` tracks retries.

**durable operations** - `packages/operations/` owns operation records, attempts, scoped idempotency
validation, claim fencing and failure classification. Claim acquisition increments and reads its fence
inside one PostgreSQL transaction so a lease takeover cannot replace an earlier claimant's returned
version. `apps/api/` records intent before queue publication. `apps/workers/` owns all BullMQ consumers,
recoverable-intent reconciliation and tracked drain. Redis delivery is at least once;
`OperationEffect.operationId` ensures duplicate delivery cannot create a second durable effect.

**depends on**
- `@rostra/config` for log level, `DATABASE_URL`, `REDIS_URL`, env mode
- `@rostra/database` types generated from `packages/database/prisma/schema.prisma`
- `pino`, `ioredis`, `keyv` and `@keyv/redis` stay behind their owning packages

**imported by**
- the gateway client, command pipeline, jobs and feature modules

## gotchas

- Phase 00 target ownership and security priorities are binding in
  `docs/architecture/decisions/011-revamp-contract.mdx`. Logger, database and cache are public workspace
  packages; tenant, scheduler and other gateway-only services remain under `apps/gateway/src/services/`.
  Owner IDs must never grant implicit guild access. Existing bypass behavior requires a tested
  security change in its owning slice. Run `pnpm check:boundaries` before committing shared changes;
  the source guard includes container shell scripts alongside JS/TS and JSON. Private archives and
  scratch are excluded from repository tools and Docker contexts.

- Construct the Prisma client **only** here (`getPrisma()`); this is an invariant.
- Prisma 7: the client needs the `@prisma/adapter-pg` adapter (`new PrismaPg({ connectionString })`),
  fed from `config.database.url`. Never read `process.env` here. The CLI side (migrations) reads the URL
  from `prisma.config.ts`, which loads `.env` via `dotenv` locally and uses real env vars in CI/Docker.
- Logger redacts token/password/auth fields, including authorization headers, and must never log
  implementation provider names.
- Without `REDIS_URL` the cache is per-process memory (not shared across shards) - fine for dev, not prod.
- `getPrisma()` does not connect on construction; first query connects.
