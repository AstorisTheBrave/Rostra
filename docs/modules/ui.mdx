## what this is

The bot's UI toolkit - a single place that exports every reusable building block for what users see and
click (buttons, menus, modals, confirm dialogs, settings toggles, pagination, layout containers). Like a
component library (shadcn-style) but for Discord's Components V2. Future features import ready-made pieces
instead of re-writing builder boilerplate.

## technical map

**file paths**
- barrel (import from here): `packages/discord-ui/src/index.ts` -> `@rostra/discord-ui`
- interactive primitives: `packages/discord-ui/src/interactive.ts`
- higher-level patterns: `packages/discord-ui/src/patterns.ts`
- layout primitives (re-exported): `packages/discord-ui/src/components.ts`
- tests: `packages/discord-ui/src/ui.test.ts`

**import** - use the public `@rostra/discord-ui` export.

**primitives (interactive.ts)** - `button(spec)`, `linkButton(label,url)`, `actionRow(...)`,
`buttonGrid(buttons)` (auto-chunks to 5×5), `stringSelect(id, options, opts)`, `modal(id, title, inputs)`,
`textInput(spec)`.

**patterns (patterns.ts)** - `confirmRow(prefix)` (Confirm/Cancel), `toggleButton(prefix, key, enabled,
label)` + `settingsPanel(prefix, items)` (on/off config grid), `paginatorRow(prefix, page, totalPages)`
(prev/indicator/next with auto-disabled edges).

**layout (from components.ts)** - `container`, `text`, `section`, `gallery`, `divider`, `Accent`,
`buildResponse`, and the `reply.*` helpers.

**emojis (emojis.ts)** - `emoji(name)` returns a custom application emoji `<:name:id>` if one has been
uploaded, else a unicode fallback, so UI looks fine immediately. `EMOJI_FALLBACK` is the semantic registry
(status + per-module + system/stats + controls); `EMOJI_NAMES` lists the keys. Custom art is generated and
uploaded by two build-time scripts:
- `pnpm emojis:generate` - rasterises Lucide icons onto coloured badges (white stroke on a rounded
  accent square, 128px) via `@resvg/resvg-js` into `assets/emojis/<name>.png`. Mapping lives in
  `apps/gateway/src/scripts/generate-emojis.ts`.
- `pnpm emojis:upload` - uploads those PNGs as the bot's **application emojis** (usable in every server)
  and writes their ids into `packages/discord-ui/src/emoji-ids.json`. Idempotent (reuses existing by name).

Both scripts and their deps (`lucide-static`, `@resvg/resvg-js`) are devDependencies; the runtime only
reads `emoji-ids.json` (ships empty -> all unicode until uploaded).

## gotchas

- **customId convention is the contract:** patterns emit ids like `module:action:arg`. The owning module's
  `ComponentHandler` (prefix = module name) provides the behaviour - the library gives you the Button, you
  wire the "onClick". Keep prefixes unique per module.
- `button()` always sets `disabled` to a concrete boolean. Action buttons need `id`; link buttons need `url`
  (mutually exclusive).
- The package root exports layouts, interactive primitives, patterns, emojis and acknowledgement helpers.
- `reply.components()` accepts button and select action rows alongside containers (the `TopLevel` type
  includes `ActionRowBuilder<ButtonBuilder | StringSelectMenuBuilder>`), so a panel can mix a `container`
  with a `stringSelect`/`paginatorRow` in one V2 reply.
- Pure builders, no side effects - fully unit-tested.
