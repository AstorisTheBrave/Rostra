# Workspace overview

Rostra is a Discord bot with a growing set of web and service boundaries. This page is a quick map for contributors. Start with the [architecture map](architecture/index.mdx), then open the relevant module guide.

## What works today

The Discord runtime lives in `apps/gateway/`; 42 feature modules live in `modules/`. The checked-in registry declares their IDs and imports, and `@rostra/module-sdk` validates and orders them. Recorded fixtures preserve 47 command definitions and 48 events without logging into Discord or publishing commands.

The API and workers are separate applications. PostgreSQL stores durable operation intent before Redis delivers work. The web application supports fixture-tested login and persisted, read-only guild summaries through a typed API client. Realtime and Activity are authenticated scaffolds, disabled by default. These boundaries and their limits are described in [capability status](product/capability-status.mdx).

## Where things live

- `apps/gateway/` - Discord sharding, interactions, events and checked-in module loading
- `apps/api/` - authenticated domain routes, health checks and external webhook boundaries
- `apps/web/` - public routes, member shell, OAuth flow and typed API reads
- `apps/workers/` - durable queue consumers, reconciliation and shutdown drain
- `apps/realtime/` and `apps/activity/` - optional authenticated application seams
- `modules/<name>/` - current feature logic, commands, events, jobs and tests
- `packages/` - shared authorities and public contracts; each package has an explicit export map
- `integrations/` - authorized adapters to external services
- `games/core/` - pure game contracts and fixtures
- `infra/` - Compose profiles, container startup and operational tooling
- `tooling/` - repository checks, fixtures, migration proofs and smoke tools
- `docs/modules/` - feature-specific behavior and ownership notes
- `docs/runbooks/` - deployment and recovery procedures

## Shared authorities

- `@rostra/config` is the only runtime environment reader.
- `@rostra/database` owns the Prisma client and schema at `packages/database/prisma/`.
- `@rostra/cache` owns Redis access and the shared bus.
- `@rostra/logger` owns structured logging and redaction.
- `@rostra/i18n` owns translation contracts and bundles.
- `@rostra/discord-ui` owns Discord Components V2 construction and acknowledgement helpers.
- `@rostra/contracts` owns cross-package job and event contracts.
- `@rostra/module-sdk` owns manifests, lifecycle contracts and the temporary compatibility adapter.
- `@rostra/auth` owns host and tenant-scoped authorization contracts.
- `@rostra/operations` owns durable operation intent, idempotency and claim fencing.
- `@rostra/web-client` and `@rostra/web-ui` provide typed web reads and shared accessible UI.
- `@rostra/testing` provides isolated test fixtures.

Packages export source through explicit public maps and use strict ESM. Do not import another package's private files. The `@/` alias remains only in the gateway and legacy modules until the compatibility loader is replaced.

## Data and recovery

PostgreSQL stores application data and durable operation intent. Redis is an at-least-once delivery mechanism; workers must tolerate duplicate delivery and the reconciler republishes recoverable intent. Migrations are forward-only and preserved in `packages/database/prisma/migrations/`. Migration failure stops application startup.

The Compose default profile runs PostgreSQL, Redis, gateway, API, workers and web. Realtime and Activity are opt-in. Database migrations use a direct connection. See [deployment](runbooks/deployment.mdx) and [recovery](runbooks/recovery.mdx) for operational details. Web sessions are currently process-local, which limits the web app to one instance.

## Important boundaries

- Guild actions and private reads require explicit authorization scoped to the requested guild. Host operator access does not bypass guild permissions.
- Migration and registry checks use fake credentials and do not login to Discord or publish commands.
- Discord UI uses the shared Components V2 package; user-facing text follows the shared localization contract.
- No ingress-provider control plane is implemented. Reverse proxies and tunnels remain passive hosting choices.
- Realtime and Activity scaffolds do not establish multiplayer or device verification.
