# Phase 01 recovery evidence

| Failure | Recovery behavior | Proof |
| --- | --- | --- |
| API cannot publish to Redis | PostgreSQL operation and outbox remain durable; API reports accepted with delayed delivery | Outbox unit and service tests |
| Redis server is unavailable | Finite producer fails promptly, outbox becomes retryable, a replacement Redis server receives the retained intent, and one durable effect completes | Task 8 real-container outage/replacement proof |
| Worker stops after a retryable effect | Replacement worker reclaims execution with a new fence; duplicate effect insert is ignored | Worker service integration |
| Worker repeatedly receives `SIGKILL` | PostgreSQL task remains recoverable through three replacement rounds with one durable effect | Scheduler process test |
| Outbox publication occurs without settlement | Expired publication claim is reclaimed using the same deterministic BullMQ job identity | Worker service integration |
| Prior image writes without a new outbox row | Each relay poll repairs a bounded batch before claiming due rows | Rollback repair service test |
| Cache publication fails | Direct PostgreSQL reads continue and process-local entries expire within five minutes | Cache unit and two-process service tests |
| Scheduled handler fails permanently | Terminal failed row, code, attempt count and claim version remain inspectable | Operations scheduler service test |
| Migration is recorded failed | Startup exhausts its configured attempts and never executes the application command | Real PostgreSQL Task 8 rehearsal |

Redis delivery remains at least once. Idempotent handlers, deterministic job IDs and fenced settlement
make repeated delivery safe for the tested effects. The evidence does not claim exactly-once Discord
side effects. Recovery retains forward migration history and supports a prior image only where the
additive schema remains compatible.
