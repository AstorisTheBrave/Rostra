# Phase 01 security evidence

## Tenant isolation

- Guessed or swapped operation IDs return the same not-found response as absent records.
- Host principals cannot read guild-scoped private operations or perform guild actions.
- Configured owner IDs no longer bypass moderation, ticket or shared member permission checks.
- Composite same-guild foreign keys prevent cross-tenant role assignment and capability grants.
- Unknown capability strings are rejected at the signed-principal boundary.

Private operation reads re-resolve current persisted membership and grants. Focused tests prove an
allowed read becomes 404 after either is revoked. This is not a universal stale-session claim: the
read-only configured-status summary deliberately remains available to a still-valid signed exact-guild
session until a production membership synchronizer exists.

## Operational boundaries

Public health endpoints expose only status. Gateway, API and worker diagnostics require the host bearer
token. Worker readiness uses finite Redis behavior, bounded dependency timeouts and coalesced unresolved
probes. Cache invalidations carry a version and exact tenant scope; stale or malformed messages are
ignored.
