# Technology stack

Rostra uses a pinned pnpm workspace and strict ESM TypeScript. This page describes the technologies in the current tree; it does not make a capacity or hosting claim.

## Runtime and workspace

- Node.js `22.22.2+` or `24.15.0+`, with later supported majors allowed by `package.json`.
- pnpm `12.14.0`, pinned through the root package manager field, plus Turborepo for workspace tasks.
- TypeScript strict mode, `tsx` for local TypeScript execution, Biome for lint and formatting, and Node's test runner.
- Gateway apps use discord.js v14 and native sharding. Hybrid clustering is an optional mode that needs Redis.

## Services and data

- PostgreSQL via Prisma 7 and the PostgreSQL adapter. The database package owns the single client, schema and migrations.
- Redis via ioredis, Keyv and BullMQ for shared cache and at-least-once work delivery. A per-process fallback exists for selected local paths, not for production queue sharing.
- Fastify for API and health boundaries; Pino for structured logs; Zod for validated inputs and configuration.
- The web application uses React, TanStack Start/Router and Vite. Playwright covers the browser smoke path.

## Ownership

See the [architecture map](architecture/index.mdx) for the owner of each app and package. Shared implementations remain behind `@rostra/*` exports. Add a dependency only to the owning workspace and check the root lockfile, package boundaries and deployment support before adoption.

## Limits

The current evidence is test and smoke evidence, not a load test. It does not establish a shard ceiling, production latency, availability target or cost estimate. The web session store is in-memory and does not support multiple replicas.
